# OKR 自评写作

## 概述

- 输出可直接提交的中文绩效自评、评分总结或价值观案例表述。
- 先吸收用户给出的目标、结果、分数和范例，再按 STAR 的内在逻辑组织内容，但最终不要显式写出 S、T、A、R 标记。

## 先判断任务类型

- `OKR / KR 自评`
- `价值观自评`
- `综合评分总结`

如果用户一次给多个 KR，按 KR 分段输出；如果用户要求总评，在末尾追加整体总结。

## 提炼输入信息

优先抽取以下信息：

- Objective 或本周期重点
- KR 内容或考核项
- 完成情况与关键动作
- 数据结果、指标变化、影响范围
- 用户指定分数、等级和语气
- 用户认可的范例风格
- 绩效表单、PDF、截图中的字段名称或口径

信息不完整时：

- 只补齐轻量过渡和结构，不补造核心事实。
- 可以将零散动作归纳成 1-3 项关键举措。
- 可以把定性结果改写成业务影响，但不要伪造具体数字。
- 如果用户给了范例或表单，优先对齐其段落长度、措辞风格和评分口径。

## OKR / KR 自评写法

按下面的顺序组织内容：

1. 开篇点明本周期的核心目标、工作重心或攻坚方向，并说明这些工作要解决的问题或要达成的价值。
2. 概括 1-3 项关键行动，使用明确动词，避免流水账式罗列。
3. 写清 KR 的完成情况，优先使用数据、比例、变化幅度、效率收益、质量改善或用户影响。
4. 收束到目标匹配度，说明成果意义，并明确给出自评分数。

建议使用的自然表达：

- 围绕……推进
- 聚焦……优化
- 推动……落地
- 通过……提升
- 进一步增强 / 降低 / 缩短 / 稳定 / 沉淀
- 最终带来……

避免：

- 空泛口号
- “首先、其次、最后”式堆砌
- 只写做了什么，不写为什么做、结果如何
- 为了凑篇幅把同类动作拆成很多碎点

## 价值观自评写法

按下面的顺序组织内容：

1. 开篇点明本周期重点践行的价值观。
2. 选一个具体场景，交代背景与任务。
3. 写清“我”如何判断、补位、推动、协同或创新，突出与价值观定义相契合的行为。
4. 如有合适结果，简洁写出影响。
5. 最后说明该案例为何体现该价值观，并给出分数和等级。

重点：

- 例子要真实、具体，避免空泛表态。
- 行动与价值观的关联要自然，不要生硬上价值。
- 结果可以简写，但行动逻辑必须清楚。

## 评分与语气

评分口径优先以用户提供的标准为准；如果没有额外标准，读取 [score-and-style.md](references/score-and-style.md) 对齐常见写法。

- `1.0`：突出超额完成、远超预期、额外价值与显著结果，语气更自信。
- `0.7`：强调目标已完成、达到预期、行动有效，语气平实肯定。
- `0.5`：强调大部分达成，既写成果，也客观交代未完全闭环部分。
- `0.3`：强调仅完成部分内容，客观说明阶段性进展和差距，避免拔高。

## 风格要求

- 默认使用中文书面语。
- 保持专业、精炼、自然，避免明显的 AI 腔。
- 强调结果导向和主动性，但不过度包装。
- 尽量用因果关系把“目标、动作、结果、价值”串起来。
- 如果用户给了最终认可的范例，优先模仿其节奏、语感和收束方式。

## 输出要求

- 默认直接输出可提交版本，不额外解释方法论。
- 如果用户只给原始要点，先整理逻辑再成文，不要照抄笔记。
- 如果用户要求“更像人写的”，优先压缩套话，增强动作与结果之间的因果表达。
- 如果用户给了固定格式或字段标题，严格按其格式输出。

## 快速检查

- 是否点明了目标，而不是只罗列事项
- 是否提炼出了 1-3 项关键动作
- 是否写清了完成情况和业务影响
- 是否与目标分数匹配，没有过度拔高
- 是否自然流畅，没有明显模板味
- 是否在结尾明确写出分数或等级
